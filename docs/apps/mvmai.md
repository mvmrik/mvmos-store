# mvmAI

Pin a conversation to keep it first and prevent automatic archiving. Use right-click or long press for Pin, Unpin, Rename and Archive; on a phone, swipe left to reveal the action buttons. Unpin a chat before archiving it. Sending a new message moves its conversation to the top of the unpinned list. Opening an old conversation or receiving an answer does not change that order. Projects follow recent use, while automatic archiving follows the last sent message rather than merely viewing a conversation.

Administrators can click the provider and model above the composer to choose them for a new chat or change them in an existing conversation. A model change keeps the conversation history and adds a visible note; saved answers show their provider. A running reply must finish or be stopped before switching its model. Switching to another chat leaves its work running, and Send now on a queued message interrupts the current reply to send that message next. Usage bars show supported CLI subscription limits and reset countdowns as rounded squares progressing from green through yellow and orange to red, with readable labels and backgrounds that follow the theme. Tap the bar on a phone to cycle through available limits. A failed or slow refresh never empties the bars: the last good reading stays until a new one replaces it. A compact activity graph and elapsed timer appear while waiting for an answer; the graph rises when new CLI output arrives, with any burst lifting it well up and larger ones to the top so every CLI reads clearly, and settles to a faint pulse when no new output arrives. The same graph appears behind a working chat in the sidebar, without an extra status row or timer. Graph height reflects incoming activity, not reasoning complexity; API providers without activity events keep a flat line. New answers retain their response duration next to the date and time, including after reopening the chat.

With no project selected, the sidebar shows every conversation from every project, newest first, and each one says which project it belongs to or that it has none. The Projects list starts with No project, which shows only the conversations without a project; choosing a project shows only its own, as before, and choosing the same entry again returns to the full list. A new conversation started from the full list or from No project has no project; started inside a project it belongs to that project. The archive follows the same choice: its count and list cover everything on the full list, only the project's own inside a project, and only the conversations without a project under No project, and Delete all archived removes only what is listed. Under the conversations a single row shows the current branch on the left, with icons on the right to expand the project's files and the archive.

When the assistant offers a picture (PNG, JPEG, WebP or GIF) as a file, the chat shows it as a preview above the download button, and clicking it opens it larger. Opening a saved conversation scrolls to the newest messages after the view finishes loading.

Projects accept typed instructions and an optional instructions file when created or edited. Relative file paths resolve against the project folder, and the file is reread before every message. The current branch remains visible when View files is collapsed. Expanding View files displays the file tree once it is ready, without an intermediate loading layout, and reuses an already loaded tree. The Files gallery shows the current project’s files first and keeps other files in an expandable group.

Administrator downloads are copies in the profile’s dedicated chat-files folder. Deleting an archived conversation removes its attached files and download copies, retaining files still referenced by another chat and leaving project originals untouched. The deletion confirmation explains this cleanup. The desktop Premium terminal opens an interactive shell in the current project folder, or the signed-in Linux user’s home folder outside a project.

## Conversation compaction

When mvmAI summarizes older messages, chats with a saved Claude or Codex session also request native context compaction in that same session. The chat keeps its provider session ID. Claude must report a compaction boundary and a successful result; Codex must report a completed context-compaction item and successful turn. Only then does the interface replace older messages with its summary. A failed operation retains the visible history and reports that compaction failed. Maintenance and regular messages for the same chat run in sequence, and an outdated maintenance request is rejected before making AI calls.

This maintenance uses the chat’s pinned provider and model and consumes provider usage, including the summary request. Gemini continues to use its existing automatic context management; this integration does not add manual Gemini compression. Providers without an mvmAI-managed persistent CLI session receive the summarized conversation on subsequent requests.

## Desktop terminal

mvmAI’s Premium terminal is an interactive shell beside the desktop chat. It starts in the active project folder, or the signed-in Linux user’s home folder outside a project, and works with any AI provider. It can float over the chat, dock on the right or bottom, or stay pinned to a conversation. With `tmux` installed, hiding or reconnecting keeps the shell running; closing the terminal ends its shell session. The terminal is available only on the desktop.

## Live progress, code and Git diffs

CLI chats display supported public messages and tool activity directly in the conversation while a task runs, without a separate scrollable progress box. Received events appear one at a time with about 350 ms between them and a brief entrance animation; reduced-motion preferences disable the animation. New events scroll the conversation to the latest activity. Commands start collapsed as a single-line preview with a status label. Expanding a command reveals its highlighted code and output; a status update preserves a manually expanded command. When the turn finishes, progress collapses into **Live progress**, which can be reopened in the current view. Final answers are never delayed by the display queue: any remaining events are retained inside the collapsed archive. Progress previews are transient and do not enter model history; reopening a saved conversation retains the final answer rather than the live event panel. Private reasoning and CLI session metadata are excluded. The server retains at most 100 public activity events per turn and polling requests only events after the client's cursor. Provider support varies: Codex agent messages and tool events and Claude streamed public text, tool inputs and matching tool results are recognized; this does not add streaming to API providers.

Fenced code blocks in messages have local syntax coloring for supported programming languages. Unknown languages remain plain code. Code and diff content is escaped before display. These previews do not send additional AI requests or add AI tokens.

In an administrator's Git project, **Git changes** lists Git-changed files whose modification time is at or after the message's start time. This only filters the file list: green `+` and red `−` counters and the read-only diff continue to include all current changes in each selected file compared with HEAD, including earlier uncommitted work. Existing untracked files are selected by the same timestamp rule. Deleted paths have no file modification time and are omitted from the time-filtered list. Concurrent manual edits or work from another chat may also appear. Filtering uses local filesystem timestamps, without file snapshots, additional AI requests or additions to model history.

The list is absent outside Git repositories. Binary files and untracked files above 2 MB have no line counters. File previews are capped at 512 KB. The diff endpoint requires an authenticated administrator and confines paths to the selected project, including resolving symlinks. External diff commands and text conversions are disabled. The branch indicator continues to reflect the repository's branch independently of the filtered file list.

Run the isolated Python checks with `venv/bin/python -m unittest discover -s apps/mvmai/tests -v`. They cover event filtering, bounded storage, polling ownership, final event delivery, Git additions/deletions, new files, unborn repositories and path confinement. No live chat data is used. Timestamp-filter tests verify that older files are hidden while selected files retain their full counters and diff. Compaction checks also cover provider completion signals, session ownership, outdated requests, failure handling and per-chat serialization. Run `node apps/mvmai/tests/test_compaction_client.cjs` to check that the interface waits for confirmation and retains history on failure.

The isolated browser checks run with `node apps/mvmai/tests/test_live_browser.cjs` when Playwright and its Chromium browser are available. `MVMAI_PLAYWRIGHT_MODULE` and `MVMAI_CHROMIUM` can point to an external installation. They verify desktop and mobile pacing, inline scrolling, final collapse, queued event retention, compact command expansion, Git counters and diff navigation.
