# mvmAudio

mvmAudio combines music, chapter-based audiobooks and live radio. The mvmOS desktop and `/pub/mvmaudio/` use the same Apps Hub identity, library and listening state. The app is under development and is not published in a Store category or release archive.

## Listening

Discover shows recent additions and unfinished audiobooks. Music, Audiobooks and Radio have separate views. Search matches the title, artist/author, genre and album/series. Genre filters and title/creator sorting help browse larger collections. Audiobooks also have not-started, in-progress and finished filters.

Each profile has its own favourites, recent listening history, playlists, bookmarks, completion flags and audiobook chapter/second/speed. A shared book never shares progress between listeners. The library shows percentage completed and remaining listening time adjusted for the saved speed. The player saves approximately every ten seconds, on pause and seeking, and attempts a final save when leaving the page. An internet connection is required for synchronization; concurrent devices use the last saved position.

The player stays mounted while browsing. It supports a reorderable queue, shuffle for music, repeat, 15-second rewind, 30-second forward, chapter navigation, speed from 0.5× to 3×, bookmarks, and a sleep timer in minutes or at the end of the current chapter. On a narrow screen, tap the current artwork to open playback options. Books advance through their own ordered chapters before the next queue item.

Supported browsers receive Media Session metadata and controls for the lock screen and headsets. Start playback before locking a phone. Browser and Android battery settings can affect background playback; real-device testing is required. The platform supplies its normal PWA install flow. PWA installation does not provide offline downloads or guarantee uninterrupted background playback.

## Common library

On the desktop, **Manage library** switches to administrator tools. Add in Music or Audiobooks opens a file-first batch upload. Select up to 200 files, their type and metadata language, then upload without entering titles individually. Embedded tags and covers are read automatically, with filename guesses used only as a fallback. Enter details manually retains the previous title-first workflow when needed. A book may contain a single long file or multiple chapters. Files are initially sorted naturally by filename; open a title to reorder or remove chapters and add more files. Music uploads can create a separate song for each selected file. Public playlists made in management mode are visible to all profiles.

Radio entries require a direct HTTPS audio stream. Station websites and M3U/PLS playlist files are not resolved. HTTP streams are not proxied; secure pages would block them as mixed content. Codec support and station-side restrictions depend on the browser. Radio is live and has no saved seek position.

## Personal library and Premium

Personal uploads are disabled by default. The desktop **Settings → Personal uploads** control is always shown. Without Premium it uses the platform subscription modal. With the Premium module and an active subscription, the administrator can set a total MB allowance per Apps Hub profile. Zero disables uploads; the setting applies independently to every profile. Public listeners see upload controls only when enabled, with no Premium purchase promotion.

The server checks stored bytes and concurrent upload reservations. Disabling uploads, lowering the allowance, or removing Premium does not delete existing files or progress. Existing private titles can still be played, edited and deleted. Administrator uploads to the common library and all personal playlists, favourites, bookmarks and progress are included in the base app.

## Playlists and sharing

Any profile can create playlists from common titles and their own uploads, choose their order and share a playlist with selected Apps Hub profiles. Search by username or display name to add a recipient. A recipient can listen to the playlist's private titles but cannot edit the owner's title or redistribute a private upload in another playlist. Removing a recipient or item revokes subsequent authenticated access; bytes already buffered by a browser cannot be recalled. Each recipient's listening state remains independent.

## Storage and administration

Runtime metadata is in `apps/mvmaudio/data.db`. Original audio files are in `apps/mvmaudio/uploads/`, outside `public/`. Preserve both when backing up. They must not be included in Store archives. Files are streamed through authorization checks and short-lived, track-specific tickets; range requests allow seeking without downloading a whole audiobook first. The stream ticket is checked against the live Apps Hub session and sharing permissions on each request.

Audio inspection is bundled with the app: an unmodified, MIT-licensed copy of TinyTag 2.3.2 reads MP3, MP4/M4A/M4B, Ogg/Opus, FLAC and WAV; bounded Python readers handle ADTS AAC and WebM, including recordings with no declared duration. Installation and runtime require no FFmpeg/ffprobe, pip packages, system commands or metadata API. The root-level `audio_probe.py`, `audio_metadata.py` and `tinytag_vendor.py` travel with the normal Store package and stay beside `api.py`; the license and provenance are in `public/tinytag-NOTICE.txt`. Accepted extensions: MP3, M4A, M4B, AAC, OGG, Opus, FLAC, WAV and WebM. A file must contain an identifiable audio stream and a finite positive duration. Header/container inspection does not decode every compressed audio sample; browser playback remains the final codec compatibility check. WebM Vorbis recordings without duration metadata use the final packet interval to estimate the ending. The per-file ceiling is 4 GiB. The browser sends files in requests of at most 8 MiB, allowing long audiobooks to pass through proxies with smaller per-request body limits. The final request checks the complete byte count and audio structure before publishing one track. Network failures retry a part without appending it twice. The upload dialog distinguishes transfer progress from checking/saving and reports confirmed saves only. Cancellation removes staged files; uploads abandoned for over 24 hours are cleaned on a subsequent upload. Personal storage is reserved for the whole declared file before its first part, so splitting cannot bypass the quota. A proxy configured below 8 MiB can still reject a part. Playback codec support varies by browser. Audio is stored in its original format; there is no transcoding, DRM service, station proxy or offline download system.

All server code lives in the app folder. The Premium policy, personal creation and upload workflow are in `premium/backend.py`, excluded from public archives and version control. All UI translations are in the app's `public/i18n.js` for the nine platform languages.

## Information and cover

Uploads automatically read supported embedded tags and cover art with the bundled TinyTag reader. Empty artist/author, album/series, genre, year and description fields are filled without replacing manual values. Chapter titles come from their own tags, independently of the book title; a music item named exactly after its file can adopt the embedded song title. Missing or oversized optional tags do not reject otherwise valid audio. Original audio files are never rewritten.

Open an owned title, or a common title in desktop management mode, and choose **Information & cover**. **Read file tags** rescans existing uploads; **Replace filled fields** permits explicit replacement. For a book, an embedded album is preferred as its title, with a single-file title as fallback, so an ordinary chapter title does not rename an entire multi-file book. You can also edit year, language, ISBN and narrator manually.

**Search online** sends only the entered title, artist/author, album or ISBN from this mvmOS installation directly to MusicBrainz (music) or Open Library (books). Audio files and credentials are never sent, no mvmOS central proxy is used, and users supply no API keys or install extra packages. Search is initiated by the user, not by a background library crawl. Results show the candidate title, creator, release/album, available cover and provider. Choose a result, review the fields, and apply the checked values. Existing fields and covers start unchecked, but remain selectable: explicitly checking a value allows it to replace the existing one. The replacement checkbox selects filled values too. Metadata is applied only to the selected language; artwork is shared across language variants. Lookup failure leaves the library unchanged.

MusicBrainz searches recordings and their releases, with release-specific year and Cover Art Archive artwork. Open Library results describe a work, so they do not populate an audiobook's narrator, audio-edition year, ISBN or language from an arbitrary print edition. Its cover is displayed directly from `covers.openlibrary.org` as requested by the Covers API guidelines. MusicBrainz cover images are fetched through the Cover Art Archive and stored locally. Provider links are retained for attribution. A missing cover never removes an existing one.

Search results are cached locally for seven days (empty results for one day). A SQLite-backed schedule spaces provider requests by at least 1.1 seconds across this app's users/workers. Busy providers return a retry message. HTTP requests accept only fixed provider domains, bounded responses and verified redirects; a client cannot ask the server to retrieve an arbitrary URL. External APIs remain subject to their own availability and usage rules.

Manual PNG/JPEG/WebP cover upload and removal are also available, with a 2 MiB limit. Embedded/manual artwork is stored in the app database behind the same ownership/sharing rules as audio, and displayed in the library, title details and player. Supported browsers also receive artwork through Media Session. Covers and metadata are base features, independent of Premium; the personal audio upload allowance continues to govern audio files. Artwork and metadata live in SQLite separately from that audio-byte allowance.

## Verification

Run `venv/bin/python apps/mvmaudio/tests/test_api.py` from the installation root. The tests use a temporary copy, synthetic audio and fictional profiles; they do not change live accounts or content. They cover independent state, chapter order, common and private playlists, authorization, sharing revocation, authenticated byte ranges, upload reservations, quota limits, disabled/missing Premium, invalid files, bookmarks and cleanup. Chunked-upload tests cover a synthetic 640 MiB audiobook, retries, offsets, authorization, quota reservations, cancellation and invalid-file cleanup. Audio upload tests run with an empty PATH and external process creation forbidden. Synthetic fixtures cover every advertised format, video-only and malformed files, and WebM recordings with unknown cluster sizes. A separate clean-install check rebuilds the Store file layout and runs the bundled reader in an isolated Python interpreter with site packages disabled, no executable search path, and network/process calls forbidden. Fixtures are pre-encoded test data, so running the tests requires no audio tools.

For the browser suite, start `venv/bin/python apps/mvmaudio/tests/test_api.py serve` in one terminal, then run `MVM_AUDIO_PLAYWRIGHT=/path/to/playwright-core node apps/mvmaudio/tests/browser.cjs`. The fixture binds only to `127.0.0.1:2087`. It tests desktop and phone layouts, resume/speed, navigation without stopping, settings, completion, playlists, sharing, bookmarks, multiple uploads, and public/desktop behavior without Premium. Temporary screenshots go to the system temporary directory. This suite uses Chromium and does not substitute for testing an actual locked Android device.

The focused browser upload regression suite is `tests/upload-browser.cjs` (same fixture server and Playwright setting). It checks a proxy-style HTTP 413, truthful failure text, transfer-versus-save status, 17 MiB across multiple requests, and a committed part whose response is lost and safely retried.

The focused `tests/metadata-browser.cjs` suite uses deterministic catalogue fixtures to check search, preview, selecting fields, preserving manual values, applying results, artwork display/upload/removal, rescan, and phone layout. API tests cover embedded ID3 artwork, lookup caching, per-title permissions, source attribution, malformed covers, and preserving progress.

### Opening and editing library items

In desktop Management, clicking a cover or title opens the editor directly. The editor also provides metadata, cover, chapter upload/order and deletion actions. Management displays the current listener’s progress rather than an empty administrative listening profile. Editing titles or other catalogue information preserves all listeners’ track IDs, positions, favourites and completion states.

Library covers have no play overlay. Opening an audiobook displays its details and loads its saved chapter and position into the bottom player, paused. The listener starts playback from the player. Selecting a chapter or bookmark also prepares it paused. Progress is never written while an audio source or its resume position is still loading. New uploads read embedded metadata automatically; existing files can be scanned from Information & cover.

### Language variants

The title editor starts with one language block using the administrator’s interface language. Add language adds another block on demand; each language can be used once, and at least one titled block is required. The available languages come from the installation’s core language files. Fields follow the selected media type in every language block. Music shows title, artist, album, genre/category and description. Audiobooks show title, author, book series, genre/category, narrator and description, plus shared year, audio language and ISBN. Radio shows station name, genre/category and description, with the direct HTTPS stream URL immediately below the type selector; artist, album, narrator, year, audio language and ISBN are hidden. Adding another language or changing the type of a new draft updates its fields immediately. Hidden legacy values and draft values are retained rather than cleared. Files and artwork remain shared properties of the record. Saved blocks can be edited or removed.

Online lookup offers a search-language selector when multiple variants exist; a single variant is used directly. Selecting a language fills its saved title and creator into the editable query. Applying selected localizable metadata changes only that language. Cover replacement is possible by checking Cover even when artwork already exists.

Apps Hub profile language selects the displayed variant on public pages. Desktop management uses the desktop interface language. When no exact variant exists, English is preferred, then the first saved language. Browsing, details, playlists and the player use this selection; library search matches titles and creators in all saved languages. Switching the display language does not create another book or listening state.

Legacy entries retain their flat metadata until edited or opened in Information & cover, which saves a language variant without replacing files or progress. Previously supplied original-name fields are retained as an English variant during this conversion. The editor no longer exposes original-name fields. No automatic title translation or Wikidata service is used.

## Administrator listening statistics

Desktop Management includes a Statistics button, also available from the editor of a common audiobook. It reports only the common library; subscriber-owned uploads and their listening state are excluded. This is a base feature and does not require Premium. The endpoint and reader-group editing require the desktop administrator session; public Apps Hub tokens cannot access them. Only profile ID, display name and username are used to identify listeners.

The overview shows common audiobook count, distinct listeners, listeners active in the last seven days, finished and unfinished book-reader pairs, and audio bytes eligible for review. Book reports sort by file size, recent listening or title, and filter by reader, not-started books, books with unfinished listeners or review status. Each book shows file size, average saved progress across the followed reader group, last listening activity and how many members of its reader group have finished. Listener cards lead to that profile’s common-library activity across music, books and radio. Activity is one latest saved record per listener/title, not an event log or play-frequency count.

A book report lists each followed reader’s completion flag, percentage, remaining listening time adjusted for speed, current chapter and last playback timestamp. By default the group consists of everyone who started or marked the book read. Administrators can instead search Apps Hub profiles and save a specific group, including people who have not started. Every selected reader must be marked complete before the book becomes eligible for review. Clearing the group restores the default. Changing the group never changes listening progress.

Review status requires audio files and at least one followed reader. It applies only to the displayed reader group, and is a suggestion for manual review, never automatic deletion. The delete confirmation displays audio size, finished/group counts and the total number of unfinished listeners, including listeners outside a selected group. Explicitly confirming deletion removes the shared record, audio, all saved progress and its reader group. Cancelling preserves them.

Saved progress is a position rather than measured listening time: seeking changes it, and a manually marked-read book is counted as complete. Existing saved state is included immediately. Favourites alone do not count as listening. Accounts that have been deleted retain an anonymous Deleted profile label in old statistics.

The focused `tests/statistics-browser.cjs` suite uses the same isolated fixture server to check reports, progress, selected and not-started readers, filters, review eligibility, explicit deletion/cancellation, phone layout and public visibility. API tests verify independent positions, speed-adjusted remaining time, common-library scope, administrator authorization, invalid reader groups, storage totals and operation without the Premium module.

## File-first batch imports

The Add button in Music and Audiobooks opens the batch importer. Radio still opens its stream editor. The importer starts with the current section and interface language, supports multiple files and shows their count and total size before upload. Music files become individual records. For books, choose separate books or ordered chapters of one book; chapter ordering uses natural filename order. All files use the existing validated, retry-safe 8 MiB chunk upload and 4 GiB per-file limit.

New import records infer initial titles from filenames. Music filenames written as Artist - Title can also provide an initial creator. During the first successful upload, embedded metadata replaces these guesses; a book prefers embedded album, then single-file title. For a grouped book, a chapter title never becomes the book title. Ordinary catalogue edits and additional chapter uploads preserve manually entered titles. Imported metadata is stored in the chosen language variant.

The optional Find online suggestions after uploading checkbox is on by default. It sends only detected titles and creators to the existing music/book catalogues after the files have been saved. Purely numeric filenames are skipped. Suggestions are cached for review and never applied automatically; the listener chooses a candidate and the fields to apply. Catalogue failure does not discard audio. Turning off the checkbox performs local tag/cover reading only.

The review view groups uploaded chapters under their book and lists detected titles, creators, artwork, sizes, missing information and available online matches. Each record can be edited or opened directly in the existing metadata preview. Saving an edit returns to the same review view. A failed file is shown separately; other files continue, and successful uploads are retained. Cancelling stops remaining work without removing successful uploads. Empty auto-created records are removed after failure, while cleanup refuses records containing audio or manually edited placeholders. Lost final responses are reconciled against the upload’s track ID to avoid reporting a saved file as failed or counting older grouped chapters as a new success.

Desktop administration imports into the common library without Premium. Public imports create personal records only when the existing Premium module and per-profile allowance permit them. Reservations and quota checks continue to run on the server for each file. This feature does not install tools, transcode audio or change those upload restrictions.

`tests/import-browser.cjs` covers a 20-file import, filename/tag precedence, language variants, suggested matches without automatic changes, editing, phone layout, partial grouped-chapter failure and the personal upload routes. API tests cover imported book names and artwork, cleanup ownership and session removal, preservation of manual edits/progress, and Premium upload restrictions.
